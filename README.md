# 中国旅行攻略自动规划 Skill V2

这个 Skill 将本次南京与新疆策划中有效的做法压缩成可复用流程：三平台分工、官方校验、统一 POI、单向路线、休息点、餐厅嵌入、住宿后置、完整预算、风险切换和多格式交付。

## 安装

克隆仓库后，将整个目录复制到 Codex 的个人技能目录：

```bash
git clone https://github.com/qianxudong8-png/china-trip-planner.git
cp -R china-trip-planner ~/.codex/skills/china-trip-planner
```

重新打开 Codex 后，可通过 `$china-trip-planner` 显式调用，也支持符合用途的自然语言请求自动触发。

## 以后怎么使用

直接说：

> 使用 $china-trip-planner，帮我规划从南京出发、2 人、总预算 10000 元的新疆旅行。时间未定，偏好人文和自然，希望大环线少走回头路，输出完整攻略和 PPT。

建议一次提供：

- 目的地或想覆盖的城市；
- 日期、季节或可接受时段；
- 人数和出发地；
- 总预算或人均预算，以及是否包含往返大交通；
- MUST GO / MUST EAT；
- 兴趣、节奏、步行或驾驶限制；
- 自驾、包车、公共交通等偏好；
- 希望交付攻略、PPT、表格、DOCX 或 PDF。

信息不完整时，Skill 会用显式默认值先推进；只有缺失值会改变路线是否可执行时才询问。

## 四种工作模式

1. 新规划：从需求、调研、验证到成稿完整执行。
2. 修改：添加城市、删景点、改天数或改预算时，复用已验证信息并重算路线和全量预算。
3. 更新：出发前重新检查天气、预约、营业、酒店价格、道路和交通。
4. 演示：路线稳定后生成 PPT，并加入路线图、休息点、餐厅评价、住宿与预算。

## 固定的数据文件

每个目的地保存：

- `trip-input.json`：用户条件和假设；
- `poi-ledger.json`：小红书、大众点评、高德和官方信息；
- `plan.json`：可审计的每日时间表与预算。

初始化示例：

```bash
python3 scripts/init_trip.py 新疆-2027夏季 --destination 新疆 --days 12 --people 2 --budget-per-person 5000 --origin 南京
```

校验示例：

```bash
python3 scripts/audit_plan.py 新疆-2027夏季/plan.json
```

初始化生成的是草稿，需填入每日事件后才能审计。时间必须为有效的 `HH:MM`；空计划、空白行程及非法时间会返回输入错误。只有明确标为 `rest` 或 `meal`、且不重叠时长达到 `min_rest_min`（默认 20 分钟）的事件才会重置连续驾驶计时。该阈值可调整，属于规划规则。

往返大交通是否计入预算默认保留为待确认（`intercity_included: null`）。已明确包含时加 `--intercity included`，明确不含时加 `--intercity excluded`。不要把模拟数据或旧攻略中的假设当成用户确认。

回归测试（Python 标准库，无需额外依赖）：

```bash
python3 -m unittest discover -s tests -v
```

审计命令添加 `--strict` 后，发现行程告警时退出码为 `1`；输入错误退出码为 `2`，正常通过为 `0`。详细数据要求见 [数据模型](references/data-model.md)。

## 质量底线

- 小红书只负责发现与真实体验线索；
- 大众点评负责餐厅分店、评分、人均、菜品和近期口碑；
- 高德负责 POI、入口、距离、路线和时间；
- 官方渠道负责开放、预约、门票、闭馆、道路和临时公告；
- 未查到的信息写 `【待确认】`，不编造；
- 长途路线明确休息、补给和夜间驾驶限制；
- 改路线后重算所有受影响费用；
- PPT 中 ImageGen 图片仅作氛围装饰，不能冒充真实现场。

## 实测改进与验收范围

2026-09-13 完成一次代表性真实集成验证：小红书正文与避雷搜索、大众点评具体门店及可见近期评价、高德长途及步行路线、官方公告检索、排程审计，以及 Presentations + ImageGen 制作的 9 页验证 PPT。最终文件通过结构检查与本机 WPS 逐页检查。原始取证留在本机，公开仓库不包含浏览器会话、账户信息或私人行程文件。

本次更新将发现的问题纳入可复用规则：

- 高德旧页面须刷新，核对真实端点与出发时刻；路线明显变长时重排转场、住宿、餐厅和预算，不沿用旧时间。
- 点评列表与门店详情、不同平台评分与人均分别记录；高分不抹去近期差评，单条差评不代表整体口碑。
- 预算含往返口径不明确时保留未知；初始化脚本修复原先默认包含的行为，并拒绝非有限预算值。
- 休息点距离近不代表厕所、座椅或入口已验证；地图用时、等位估计与规划缓冲分别展示。
- PPT 原生表格、图表数据、回读、实际放映检查分别验收；只对实际检查过的最终文件报告结果。

这次实测证明代表性链路可运行，不代表任意目的地均能无人介入完成。完整旅行方案仍需核对出发日期、预算范围、全部路线和报价。脚本检查、平台调研、PPT 验收和整趟行程可执行性分别报告，不能互相替代。
